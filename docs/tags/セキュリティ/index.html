    AIエージェントが「画像を貼れない」問題を勝手に解決、343組織の機密スクショ1万3000枚超をGitHubの公開リポジトリに保存していたことが判明

    AIコーディングエージェントが開発中の画面をレビュー担当者と共有する際、非公開リポジトリのスクリーンショットをGitHub上の公開リポジトリへアップロードしていたことがセキュリティ企業のGlow Securityによって明らかにされました。Glow Securityは343組織に関連する1万3000枚を超える画像を確認しており、認証情報や個人情報、未発表製品に関する情報まで含まれていたと報告しています。

    Glow: The Endpoint AI Company | PixelLeak AI exposure of private developer data

    https://www.glow.io/blogs/how-ai-agents-exposed-developer-screenshots-from-leading-tech-companies

    AI models keep posting screenshots showing sensitive data from inside tech companies

    https://www.theregister.com/ai-and-ml/2026/09/29/ai-models-keep-posting-screenshots-showing-sensitive-data-from-inside-tech-companies/5299640

    AIコーディングエージェントはソースコードを書くだけでなく、ブラウザを操作してウェブアプリを開き、修正前後の画面をスクリーンショットで確認するといった作業も行えるようになっています。例えばGitHub Copilotにはブラウザ操作機能が用意されており、ページの操作やコンソールエラーの取得、スクリーンショット撮影などをAIエージェントに任せられます。

    GitHub CopilotがVS Code内でブラウザ操作に対応、AIエージェントがウェブアプリを開いて検証可能に - GIGAZINE

    一方でGitHubにはIssueやプルリクエスト、コメントへ画像をアップロードするための公開APIがなく、GitHub CLIでも通常の本文入力では画像を添付できません。ブラウザ上では画像をドラッグ＆ドロップできますが、端末上で自律的に作業するAIエージェントにとっては扱いにくい部分です。GitHub CLIのリポジトリでも画像添付を求める要望が以前から投稿されています。

    開発者のビプル・グプタ氏は画像アップロードの手間を解消するため、AIエージェント向けのコマンドラインツール「 GitShot 」を公開しています。GitShotを使うと「gitshot screenshot.png」のようなコマンドを実行するだけで画像をアップロードし、GitHub上のMarkdownに貼り付けられるURLを取得可能です。

    GitShotは標準的なGitHub Releasesを使う設定の場合、ユーザーのアカウントに「gitshot-images」という専用の公開リポジトリを作成し、画像をGitHub Releaseのファイルとして保存します。GitShotの説明には「gitshot-imagesはデフォルトで公開リポジトリとして作成されるため、機密情報や社内ダッシュボード、個人情報などをアップロードしないように」と明記されています。

    Glow Securityによると、確認された情報流出のおよそ3分の1がGitShotを利用していた開発者に関連していました。なお、Glow Securityが「PixelLeak」と呼ぶ今回の情報流出は特定のAIモデルやGitShotに限った問題ではな…

    オープンAIのAIが暴走 米教育省、商務省、SECのサイト標的(CNN.co.jp)

    2026年9月27日 カテゴリー 未分類

    本文

    9/27(日) 15:12 配信

    31 コメント 31 件

    米オープンAIは25日、同社のAIエージェントの一部が今夏に暴走して米政府のウェブサイトを探っていたと明らかにした（Thomas Fuller/SOPA Images/LightRocket/Getty Images） （CNN） 米オープンAIは25日、同社の一部のAI（人工知能）エージェントが今夏に暴走し、米政府のウェブサイトを探っていたと明らかにした。オープンAIの技術をめぐる新たな問題が発覚した形だ。

    米紙ニューヨーク・タイムズが最初に報じた。同紙はAI研究機関トランスルースのセキュリティー研究者の話として、オープンAIのAIエージェントが暴走し、米教育省、商務省、証券取引委員会（SEC）へのアクセスを試みたと伝えている。

    オープンAIは26日、同社のエージェントがオンライン上で見つけたログイン認証情報を使って商務省国勢調査局の一般公開データにアクセスしたと明らかにした。また、別のケースでは、SECのウェブサイトにある公開データを別のウェブサイトで共有した。教育省にもアクセスを試み、公民権局からデータを収集しようとしたものの、これは失敗したという。

    オープンAIはCNNにメールで、こうした事実を各機関に通知するとともに、「モデルの逸脱した活動について広範な調査」を続けていると説明した。

    広報担当者は「これまでに調査した活動の大半は、質問に答えるために一般公開されているウェブ上のコンテンツにアクセスするといった、通常の調査作業に関わるものだった。政府のウェブサイトが関係する事例もあったが、これは当社のモデルが公開情報の信頼できる情報源として政府サイトを参照することが多いためだ」と述べた。

    今回の報道の数日前には、オーストラリアの首相が、オープンAIのエージェントが同国の国民医療データベースに不正侵入したと明らかにしていた。トランスルースは23日、少なくとも3月時点でAIエージェントが暴走した事例を検知していたと明らかにした。ニューメキシコ大学の図書館や、保健福祉に関連するオーストラリアの国立機関のサイトを標的としたものの、いずれも失敗したという。

    オープンAIは、7月に同社のAIエージェントが米AI開発企業ハギングフェイスに不正侵入して以降、調査を続けている。

    オープンAIのサム・アルトマン最高経営責任者（CEO）は25日、X（旧ツイッター）で、同社の対応が「望んでいたほど迅速ではなかった」と述べた。

    競合他社のアンソロピック、メタ、グーグルも、自社のエージェントが不正侵入を試みて暴走した事例があったと報告している。
